## 修复与复测

- Pi 空结果后不再使用整段长问题查询：注入指导先用短实体词，必要时受控缩短查询或查询当前 Agent 的近期事实；失败尝试保留，完整流程重新通过。
- Claude Code 2.1.296 的跳过历史开关会影响续聊记录；需要持久会话时保留原生历史并显式恢复对应会话，真实续聊重新通过。
- Hermes、OpenClaw 注册到 Proxy 的 Chat 路由和客户端适配表，修复原 404；保留对应连接的凭据隔离。
- CodeBuddy CLI 2.164.0 使用完整 `/v1/chat/completions` URL，原生错误事件即使进程返回 0 也不能判成功。配置格式参照[官方模型配置说明](https://www.codebuddy.ai/docs/cli/models)。
- OpenClaw 2026.10.1 的原生会话存储为 SQLite；采集改用官方 trajectory export，并处理 JSON 后的诊断日志。导出器隐藏含 JSON 的 shell 命令或查询响应时，使用同版本只读 transcript 接口补充调用 ID、接口路径、查询状态和本轮合成标识符，与原生结果关联；不导出命令、请求头、凭据或原始工具输出。
- Codex 的模型身份说明仅用于主对话；辅助请求保留原客户端指令，主对话与辅助请求的边界测试通过。
- Pi、Hermes 使用各自的原生会话 ID；Lab 启动器不再向 shell 工具导出一个不同的会话 ID。Pi 的一次未绑定查询曾返回会话不可用，旧判定将其误认为未命中；现要求成功且已认证的查询响应，保留复核失败记录后重新执行相关完整流程和共享读取。
- 共享环每条边的重试新建读者 Agent，保留写入 Agent 与全部历史。复用读者时，先前合法召回并归档在自身记忆中的事实会影响未绑定检查；已通过返回记录 ID 核对这一来源。查询 limit 为 1，避免 Hermes 原生日志截断；OpenClaw 的原生查询元数据补足诊断导出的脱敏证据。
- OpenClaw 2026.10.1 存在上游日志限制：原生脱敏函数遇到包含嵌套 shell/tool 文本的查询结果时，可将服务端有效 JSON 改为无效 JSON。已在固定镜像内直接调用两个官方函数复现，未修改其脱敏逻辑。Hermes → OpenClaw 共享查询限定到 Hermes 的真实写入会话；过滤条件放在请求体，身份头仍使用当前读者会话。三阶段权限结果仍须有成功的原生查询证据，损坏日志不计通过。此验证不代表上游日志限制已修复。
- 文件工具验收同时要求工作目录中的真实文件和客户端工具输出中的读回内容。补充审查发现 Pi / gpt-6-luna 一次旧尝试只有文件存在证据，缺少原生读回证据；保留原审查结果后按加强后的判定重跑。

失败、重试和中断记录均保留；最终结果按每个组合最后一次完整流程计算，不覆盖旧结果。
